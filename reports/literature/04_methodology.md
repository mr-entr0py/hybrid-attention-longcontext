## 0. Executive summary (what to do)

1. **Primary comparison:** the comparison is **parameter-matched** (non-embedding params equal within ±1 %), **token-matched** (identical tokens *and identical order* per seed index) and uses a **shared recipe**. FLOP-matching is reported as a secondary quantity, not used as a design constraint (§3).
2. **Architecture grid (reference L=12, d=512):** r ∈ {0, 1/12, 1/6, **1/4**, 1/3, 1/2, 1}, i.e. k = 0,1,2,3,4,6,12 attention layers. The H1 test point is pre-registered as **r = 1/4 (3 linear : 1 full)**, so there is no winner's-curse selection (§9). Default placement is "end of each group", e.g. k=3 → layers {3,7,11}. The placement study is run at k=3 (§2.4).
3. **LR fairness:** sweep 5 LRs (half-octave grid centred at 2e-3) at **r = 0, 1/4 and 1** on 4K *validation LM loss only*. Use a shared LR if the minimax regret is ≤ 0.02 nats. Otherwise per-config LR (equal-budget tuning) becomes primary (§4).
4. **Seeds:** each seed index s drives separate, derived RNG streams: init (per module), data order, and eval generation (fixed, independent). Seed index s shares the data order across all configs (blocking / common random numbers). Use **3 seeds** for the confirmatory configs {0, 1/4, 1}, 2 for curve points and 2 for placement arms. Raise to 5 if the pilot shows seed-difference SD > 5 pp (§5).
5. **Statistics:** the item is the unit and the eval items are identical for every model, so all comparisons are paired. Uncertainty comes from a **hierarchical (seed → item) bootstrap**, cross-checked by a seed-level paired *t* interval. Six pre-registered confirmatory tests use Holm (α_FW = 0.05). Exploratory cells use BH-FDR (q = 0.10). Pre-registered effect-size thresholds: **5 pp accuracy, recovery ≥ 0.8, 0.01 nats LM loss** (§6).
6. **Gates G0–G5** have numeric thresholds (§8). **Minimum experiment to falsify H1:** {r=0, 1/4, 1} × 3 seeds × (1.0B tokens at 4K + 0.1B at L_ext). That is ≈ 37 GPU-h at the conservative throughput, or ≈ 23 h idle-GPU (§10).
7. **Total budget:** about 135 GPU-h conservative (≈ 85 h idle-GPU) for the full study, A–D plus placement (§10). A 49-h Tier A is enough to settle H1.
8. **Context curriculum (identical for all configs):** 4K pre-training, then a 0.1B-token extension at 16K, or 32K if gate G4 passes. **Intra-document masking in *both* layer types**: block-diagonal attention and GDN state reset via `cu_seqlens`. Lengths beyond the trained length are reported separately as *extrapolation* (§7).
9. **Determinism:** production runs are *statistically* reproducible, not bitwise. A bitwise audit mode, a kill-and-resume test and pinned Triton autotune caches are mandatory before Stage 2. Triton autotuning in fla and in Inductor is a concrete source of run-to-run nondeterminism (§11).
10. **Infra:** frozen-dataclass + YAML configs with a SHA-256 config hash; an append-only JSONL registry; item-level JSONL eval outputs; JSONL metrics (TensorBoard optional); `systemd-run --user` jobs (needs `loginctl enable-linger`); atomic checkpoints with RNG and loader state (§12–13). Every plot is regenerated by a script from raw JSONL (§14).

## 2. Variables

### 2.1 Independent variables (manipulated)

| Factor | Levels | Purpose |
|---|---|---|
| **Composition r = k/L** (L=12) | k ∈ {0, 1, 2, 3, 4, 6, 12} → r ∈ {0, .083, .167, .25, .333, .5, 1} | RQ-A, H1, H2, H6 |
| **Placement** at fixed k=3 | `spread` {3,7,11} (default), `front` {0,1,2}, `middle` {4,5,6}, `back` {9,10,11} | RQ-B, H4 |
| *Within-model factors (evaluation):* task family | retrieval · multi-hop · aggregation (exact tasks owned by the evaluation agent) | RQ-C, H3 |
| *Within-model:* context length | 1K, 2K, 4K, 8K, 16K, 32K | H5 |
| *Robustness only (Stage 5):* PE scheme, LR (±½ octave), width, token budget | see §9 | sensitivity |

Default placement rule [I]: attention indices are `round((j+1)·L/k) − 1` for j = 0..k−1. This places attention at the end of each group of L/k layers: k=1 → {11}, k=2 → {5,11}, k=4 → {2,5,8,11}, k=6 → {1,3,…,11}. It keeps layer 0 linear for every k < L, so the first layer can learn positional information as in Waleffe et al. (L19), and it reproduces the common "3:1 interleave" at k=3.

### 2.4 Confounds and how each is handled

| Confound | Risk | Control |
|---|---|---|
| Param count differs by mixer (default GDN ≈ 6d² vs MHA 4d²; inspected in `fla/layers/gated_deltanet.py`) | Composition effect conflated with capacity | Per-block param equalisation via MLP width. Report exact counts. Tolerance ±1 % (§3.2) |
| FLOPs differ (attention is quadratic, GDN has chunk overhead) | "Hybrids win because they compute less/more" | Report measured FLOPs and tok/s. Primary claims are param/token matched. FLOP-matched is a sensitivity check (§3.3) |
| LR suits one architecture | Biased contrasts | Endpoint + middle LR sweep with a regret rule; per-config fallback (§4) |
| PE interacts with r (attention-only RoPE; GDN is implicitly positional) | H5 confounded | One pre-registered PE, chosen to favour the r=1 baseline. NoPE ablation at r ∈ {1/4, 1} (§7.3) |
| Placement confounded with ratio in the sweep (positions change with k) | H4 vs H1 entangled | Fixed placement rule for the sweep. Separate placement arms at k=3 |
| Last-layer attention | k=1 "spread" puts attention at layer 11 | Covered by the placement arms at k=3. k=1 is interpreted with this caveat |
| Data order | Spurious differences | Blocked: seed s ⇒ same data order for every config |
| Shared-module init | Extra noise in contrasts | Per-module derived init seeds give identical embeddings/MLP/norm init across configs for a seed index (§5.1) |
| Eval elicitation (small base LMs may need specific formats) | Floor effects hide differences | Identical continuation-style prompts. Gold log-prob reported. G2 difficulty calibration on *dev* items only |
| GPU contention (CARLA etc.) | Timing invalid, autotune picks differ | Cost benchmarks only on an idle GPU. Pinned autotune cache (§11). Contention flag logged per run |
| Kernel implementation quality (fla Triton vs SDPA/FA) | "Cost" reflects code, not the architecture | Report analytic bytes/FLOPs next to measured. Claims are scoped "for this implementation" |
| GDN state size (heads × d_k × d_v) | The memory axis depends on a free design choice | Fix it and report it. A Stage-5 sensitivity arm (2 state sizes at r=0) is optional |
| Corpus fixed (no train-data resampling) | Conclusions are conditional on the corpus (L1) | State as a limitation. Seeds vary order, not content |

## 3. Which comparison is primary?

### 3.1 Decision

**Primary: parameter-matched + token-matched + shared recipe.** [I] Reasons:
1. RQ-A asks about composition "when everything else is held fixed". Parameter and token matching is the standard reading, and it is what the README promises.
2. Inference-state memory (RQ-D) is the cost axis we care about. It is measured directly, so FLOP matching is not needed to make the frontier honest.
3. FLOP matching is ill-defined across lengths, because attention FLOPs depend on T and on the document-length distribution. Equalising at 4K would de-equalise at 16K.

### 3.2 Parameter-matching rule (concrete)

- Count **non-embedding** params (Kaplan, L14) as the matched quantity. Also report total params (tied).
- Per block: attention block = 4d² (QKV+O) + 2·d (QK norm gains) + SwiGLU(d, h_A). Linear block = GDN mixer + SwiGLU(d, h_G). Choose h_G (a multiple of 64) to minimise |P_A − P_G|.
- Reference numbers, computed by instantiating the modules in my benchmark (scratch, not a project artifact): d=512, h_A=1536 (attention block) and h_G=1344 (GDN block, 4 heads × 128, `expand_v=1`, short conv, output gate). Non-embedding totals: **all-attention 40,908,800**; **all-GDN 40,638,560 (−0.66 %)**; r=1/4: 40,706,120. With a tied 32,768×512 embedding the totals are ≈ 57.7M. This is inside ±1 % and inside the project's 20–60M range.
- The registry stores per-run `params_nonemb`, `params_total`, `params_attn_mixers`, `params_linear_mixers` and `params_mlp`.

### 3.3 Secondary comparisons

- **FLOP-reported:** log measured FLOPs (from the analytic formula, validated with `torch.utils.flop_counter` on one step) and wall-clock per config.
- **Equal-budget per-config tuning (robustness):** if the shared LR passes the regret rule, a Stage-5 check reruns r ∈ {1/4, 1} at each config's own best LR (1 seed) and confirms the conclusions keep their direction.
- **FLOP-matched sensitivity (optional):** give the cheaper of r=0 and r=1 extra tokens to match the more expensive config's training FLOPs (1 seed). Only needed if training-FLOP differences exceed 15 % [I].

## 4. Hyperparameter fairness

### 4.1 LR sweep (Stage 1)

- **Configs:** r ∈ {0, 1/4, 1}. Including the middle hybrid tests whether hybrid optimal LRs lie between the endpoints.
- **Grid:** peak LR ∈ {1.0e-3, 1.4e-3, 2.0e-3, 2.8e-3, 4.0e-3} (half-octave steps). The centre comes from DeepSeek's η_opt ≈ 2.0e-3 at C ≈ 3e17 FLOPs (L12; our C is at the lower edge of their fitted range, so this is only a grid centre). If any config's optimum is at a grid edge, add one more point beyond that edge.
- **Budget per sweep run:** 0.2B tokens at 4K, the same WSD shape compressed (decay over the last 25 %), seed index 100 (disjoint from main seeds), 3 × 5 = 15 runs.
- **Selection metric:** **4K held-out LM validation loss only.** Long-context task scores are never used to choose hyperparameters (otherwise the eval is contaminated) [I].

### 4.2 Decision rule (pre-registered)

Let L_c(η) be the val loss of config c at LR η, and regret_c(η) = L_c(η) − min_η' L_c(η').
- Shared LR η* = argmin_η max_c regret_c(η).
- **Accept shared LR** if max_c regret_c(η*) ≤ **0.02 nats**. That is ≈ 10× the seed SD from L8 and ≈ 0.6 % of a ~3.3-nat loss, comparable in spirit to DeepSeek's "0.25 % of minimum" band (L12).
- **Otherwise** per-config LR becomes primary. Each of r ∈ {0, 1/4, 1} uses its own best grid LR. Intermediate r use log-linear interpolation in k between neighbouring tuned points. The shared-LR results are kept as a sensitivity analysis.
- Also report the Wortsman LR-sensitivity diagnostic (L11) per config.

### 4.3 Other fixed HPs [I]

| HP | Value | Note |
|---|---|---|
| Batch | 131,072 tokens | DeepSeek B_opt ≈ 1.6e5 at C ≈ 3e17 (L12) |

## 5. Seed strategy

### 5.1 RNG streams (separate, derived, logged)

Derive every stream from `SeedSequence(entropy=PROJECT_SALT, spawn_key=(seed_index, stream_id, ...))`, i.e. `numpy.random.SeedSequence` → `torch.Generator`. Never use global RNG state in the data or eval path.

| Stream | Derivation | Shared across configs for the same seed index? |
|---|---|---|
| `init` | Per module: hash(seed_index, "init", module_path), e.g. `blocks.3.mlp.up` | **Yes for shared modules** (embedding, MLPs, norms, head). Mixer modules are seeded by (layer index, mixer type). This gives common random numbers that reduce contrast variance [I] |
| `data` | hash(seed_index, "data") → permutation of packed-sequence indices; batch b = perm[b·B:(b+1)·B] | **Yes**: identical order for all configs (blocking; L16, L17) |
| `stageB_data` | hash(seed_index, "dataB") | Yes |
| `eval_test` | constant 20261109 (one-off generation, files frozen) | Yes (identical files) |
| `eval_dev` | constant 77 (difficulty calibration only) | Yes |
| `bench` | constant 0 (random token inputs for timing) | Yes |
| `sweep` | seed indices 100–199 | Disjoint from main seeds (L3) |

Main seed indices: **0, 1, 2** (confirmatory), **3, 4** (reserve, triggered by gate G3). Pre-declared; none may be dropped or replaced. A diverged run is reported, not silently rerun (§8, G-div).

### 5.2 How many seeds

| Arm | Seeds | Rationale |
|---|---|---|
| r ∈ {0, 1/4, 1} (confirmatory, H1) | **3** (→ 5 if G3 triggers) | Paired seed-level *t* with df=2 is weak, so the item-level paired bootstrap carries most of the power. 3 seeds gives a usable estimate of σ_seed |
| r ∈ {1/12, 1/6, 1/3, 1/2} (curve) | **2** | Curve shape (H2/H3/H5) borrows strength across neighbouring points. A 3rd seed if budget allows |
| Placement arms at k=3 | **2** each, plus the 3 seeds of `spread` | H4 |
| LR sweep / pilots | 1 (plus 2 extra at endpoints for G3) | |

### 5.3 Power reasoning

- **LM loss:** L8 gives σ_seed ≈ 0.002 nats at 124M. Even if our σ is 3× larger, 2–3 seeds detect 0.01–0.02-nat differences. LM loss is unlikely to be the binding constraint; L18 found LM loss "stable across ratios".
- **Long-context accuracy (binding):** σ_seed is unknown and possibly large (L10). Let σ_d be the SD across seeds of the *paired* per-seed difference S(1) − S(r) for a family score. The contrast SE is SE ≈ √(σ_d²/S + SE_items²). SE_items ≈ 1.2 pp for a family pooled over 3 tasks × 4 in-distribution lengths × 500 items (§6.5).
  - σ_d = 3 pp, S = 3 → SE ≈ 2.1 pp → MDE (α=.05, 1−β=.8, ×2.8) ≈ **6 pp**. ✓
  - σ_d = 6 pp, S = 3 → SE ≈ 3.7 pp → MDE ≈ 10 pp. Marginal.
  - σ_d = 6 pp, S = 5 → SE ≈ 2.9 pp → MDE ≈ 8 pp.
- **Rule (G3):** if the pilot gives σ_d > **5 pp** for the retrieval family at in-distribution lengths, add seeds 3 and 4 to the three confirmatory configs (+6 runs ≈ +25 h).

## 6. Statistical analysis plan (pre-registered)

### 6.1 Data model

There is one row per (run_id, checkpoint, task, length, item_id), with `correct ∈ {0,1}`, `gold_logprob` and `cluster_id` (the haystack/template id). Family score S_f(c, L) = mean over tasks in f (equal weight per task) of mean accuracy over items and seeds.

### 6.2 Confidence intervals: hierarchical paired bootstrap (primary)

B = 10,000 replicates. In each replicate:
1. Resample **seed indices** {0..S−1} with replacement once, and apply the same indices to every config (this keeps the data-order blocking).
2. Resample **clusters** (then items within cluster) with replacement, stratified by (task, length), and apply the **same indices to all configs** (this keeps the pairing; L6).
3. Recompute every statistic (S, R, differences, k80, slopes, hull margins).
4. Use percentile 95 % CIs. BCa is a sensitivity check.

### 6.3 Seed-level cross-check (guards against L5)

Per seed index s, compute the statistic on that seed's data (items pooled). Then form a paired *t* interval across seeds (df = S−1; t_.975 = 4.30 for S=3 and 2.78 for S=5). **A claim is "supported" only if both the bootstrap CI and the seed-level t interval exclude the null/threshold.** If only the bootstrap CI does, the claim is "suggestive". All per-seed points are plotted.

### 6.4 Secondary model

The secondary model is a binomial GLMM: `correct ~ config × length × task + (1|item) + (1|seed:config)`. In Python this can be `statsmodels.BinomialBayesMixedGLM`, or GEE with clustering by item as a fallback. It is used for the interaction tests (H3, H5) and as a check on the bootstrap.

### 6.5 Item counts (Miller formula, L6)

With n = (z_{α/2} + z_β)² ω² / δ², a binary outcome near 0.5 and model-to-model correlation ρ ≈ 0.5 give ω² = Var(A) + Var(B) − 2Cov ≈ 0.25:
- n = 500 per (task, length) cell → MDE ≈ 2.8·√(0.25/500) = **6.3 pp** per cell.
- Pooled over 4 in-distribution lengths → ≈ 3.1 pp. Pooled over 3 tasks × 4 lengths → ≈ 1.8 pp.
- With clustering, multiply by the design effect, measured from cluster ICC in the pilot. If the design effect exceeds 1.5, raise n per cell to 750 for the confirmatory family.

Default: **500 items per (task, length) cell** (RULER default, L25) for final checkpoints. **100 per cell at 3 lengths** for intermediate "dev-curve" checkpoints.

### 6.6 Operational definitions of the hypotheses (confirmatory family, Holm α_FW = 0.05)

Throughout, "in-distribution lengths" ID = {4K, 8K, 16K (and 32K if L_ext = 32K)}. Gap G_f(L) = S_f(1,L) − S_f(0,L).

| H | Test statistic | Supported if | Falsified if |
|---|---|---|---|
| **H1** partial sufficiency | R_ret(r=1/4) averaged over ID lengths; non-inferiority gap Δ = S(1) − S(1/4) | lower CI(R) ≥ **0.8** AND upper CI(Δ) ≤ **5 pp** | upper CI(R) < 0.8 |
| **H2** diminishing returns | g₁ = S(1/12) − S(0) (gain of the first attention layer) vs g_late = (S(1) − S(1/2))/6 (mean gain per layer over the last 6) | CI(g₁ − g_late) > 0, per family (H2 is tested on retrieval; the other families are exploratory) | CI(g₁ − g_late) ≤ 0 |
| **H3** task dependence | k80_f = smallest k with R_f ≥ 0.8 (interpolated). Test k80_ret − k80_multihop, and similarly for aggregation; GLMM config×task interaction | Bootstrap CI of some k80 difference excludes 0 AND the interaction LRT passes | All k80 CIs overlap 0 with width ≤ 2 layers (equivalence) |
| **H4** placement | At k=3: range across {front, middle, back, spread} of S_ret; also compared with one-layer composition gain S(4/12) − S(3/12) | Holm-corrected pairwise CI excludes 0 for some pair AND range ≥ 5 pp | All pairwise CIs inside ±5 pp (equivalence, TOST) |
| **H5** length dependence | Slope b_f,r of G_r(L) = S(1,L) − S(r,L) vs log₂L over ID lengths, for r = 1/4 and r = 0 | CI(b_ret) > 0 AND a family × log₂L interaction | CI(b) ∋ 0 for all families with \|b\| < 2 pp/doubling |
| **H6** frontier | Hull margin: M(r) = S(r) − [S(0) + (c(r) − c(0))/(c(1) − c(0)) · G], with c = inference-state memory at 32K. Since memory is ≈ linear in k at long L, **M > 0 ⇔ R(r) > c-fraction ≈ r** [I] | Some hybrid has CI(M) > 0 for the retrieval family | CI(M) ≤ 0 for every hybrid |

The H6 framing is my inference: a "router" that serves fraction p of queries with r=1 and 1−p with r=0 achieves the straight line between the endpoints in expected memory and accuracy. Hybrids are only interesting if they beat that line. The test is repeated for decode throughput and prefill latency as secondary cost axes.

**Gate for interpretability:** H1 to H6 are only evaluated for a family/length cell with G_f(L) ≥ **15 pp** and S(1) ≥ floor + 20 pp. Cells failing this are reported as "non-discriminative" (gate G2).

### 6.7 Multiple comparisons

- **Confirmatory family:** the 6 tests above, Holm–Bonferroni at α_FW = 0.05.
- **Exploratory:** every other task × length × config cell uses BH-FDR q = 0.10 and is labelled exploratory.
- Bouthillier's P(A>B) ≥ 0.75 (L1) is reported for each confirmatory pairwise contrast as a "practically meaningful" companion.

### 6.8 Meaningful effect sizes (pre-registered)

| Quantity | Threshold |
|---|---|
| Accuracy difference | 5 pp (absolute) |
| Recovery fraction | 0.8 ("most"), 0.9 ("nearly all") |
| LM loss | 0.01 nats |
| Throughput / latency | 10 % |
| Memory | analytic, exact; report ratios |

### 6.9 Pre-registration mechanics

Before Stage 2 launches, freeze the following and commit them, recording the commit hash in `reports/decisions.md`:
- `reports/experimental_protocol.md`
- `src/analysis/*.py` with synthetic-data unit tests
- `configs/`
- eval item files with their hashes

Any later change is a logged deviation with its rationale.

## 7. Context-length curriculum, packing, PE

### 7.1 Curriculum (identical for all configs)

| Stage | Seq len | Tokens | Data | LR |
|---|---|---|---|---|
| A | 4,096 | 1.0B | Main corpus | warm-up → constant → decay begins at 0.825B |
| B | L_ext = **16,384** (default) or **32,768** if G4 passes | 0.1B | ≥ 50 % of tokens from docs ≥ L_ext/2 (books/code-like long docs), the rest from the main corpus (ProLong mix rule, L24) | continues linear decay to 0 |

Eval lengths 1K–L_ext are **in-distribution**. Lengths above L_ext (32K when L_ext = 16K) are **extrapolation**: they are analysed separately and never pooled into H1–H5 primary statistics.

### 7.2 Packing and masking

- Use sequential concatenation with an EOS between documents. Docs longer than the sequence length are split into consecutive chunks. Chunk boundaries count as doc boundaries.
- Log the fraction of truncated docs and the token-weighted doc-length histogram per stage. Best-fit packing (L23) is optional.
- **Intra-document masking in every layer** [I, critical]:
  - attention uses block-diagonal causal masking via `torch.nn.attention.varlen.varlen_attn` (present in torch 2.11, verified) or FlexAttention `create_block_mask`;
  - GDN resets state at boundaries via fla's `cu_seqlens`;
  - RoPE position ids restart per document.
- Applying doc masking only to attention would let linear layers carry cross-document state. That is a hidden architecture-specific difference, so it is not allowed.
- No recurrent state is carried across training sequences.

### 7.3 Positional encoding (pre-registered selection, baseline-favouring)

Linear layers get no explicit PE. Softmax layers: one scheme for all configs, chosen in the pilot (Stage 1, ≈ 4 GPU-h) from:
- RoPE θ = 1e4
- RoPE θ = 5e5
- NoPE

Each arm is trained at r=1 (0.2B at 4K + 20M at L_ext). **Rule:** pick the scheme that maximises the **r=1** model's dev retrieval accuracy at L_ext, using val loss at L_ext as the tie-break. Choosing the scheme that is best for the all-full baseline makes H1 harder to support, which is conservative.

- θ is held constant across Stages A and B (no mid-run change).
- Stage 5 runs the non-chosen scheme at r ∈ {1/4, 1} (1 seed each) to test the PE × r interaction (motivated by L19, L21).

H1's test point (r = 1/4) is fixed *before* data. There is therefore no screen-then-select step and no winner's curse. If the curve (Stage 3) suggests a smaller r is sufficient, that result is **exploratory** and needs fresh seeds (3, 4) before it can be claimed.

### Minimum experiment to falsify H1

Logic: if 3 of 12 layers do not recover 80 %, smaller fractions are very unlikely to, *assuming monotonicity in k*. That assumption is checked later by Stage 3. The cost is ≈ 37 GPU-h conservative, ≈ 23 h idle, plus ≈ 4 h of evaluation.

## 11. Determinism and reproducibility

### 11.1 Facts

- PyTorch: `torch.manual_seed` seeds CPU and CUDA. NumPy `Generator` objects need separate seeding. `cudnn.benchmark=False` and `cudnn.deterministic=True` are separate settings. `use_deterministic_algorithms(True)` raises an error on known-nondeterministic ops. For SDPA, `warn_only=True` only warns and still uses nondeterministic fused backends. Reproducibility is "not guaranteed across PyTorch releases, individual commits, or different platforms". Source: https://docs.pytorch.org/docs/2.15/notes/randomness.html [read-section].
- cuBLAS is bitwise reproducible for the same toolkit version, architecture and SM count, except with multiple streams. The fix is `CUBLAS_WORKSPACE_CONFIG=:16:8` (may cost speed) or `:4096:8` (≈ 24 MiB extra). Source: https://docs.nvidia.com/cuda/cublas/index.html#results-reproducibility [read-section].
- bf16 GEMMs use reduced-precision reduction by default (`allow_bf16_reduced_precision_reduction=True`). Source: https://docs.pytorch.org/docs/2.15/notes/cuda.html [read-section].
- **fla kernels:** Triton autotuning runs at first call per shape. `FLA_CACHE_MODE` defaults to `disabled` and `FLA_CACHE_RESULTS` defaults to `1`, i.e. Triton's on-disk autotune cache. The GDN path enables TF32 when `IS_TF32_SUPPORTED`. `tl.atomic_add` appears in path-attention, atk, cyfa, log-linear and the CSR helper, but **not in `fla/ops/gated_delta_rule` or `fla/ops/common`**. Source: `third_party/flash-linear-attention` @ `98193113` [code-inspected]. Implication [I]: GDN is deterministic *given a fixed kernel config*. Autotune choices made under contention can differ between processes, which changes the reduction order.
- **FlexAttention:** the dq/dk nondeterminism came from *autotuning of a reduction kernel*. `torch._inductor.config.deterministic = True` makes the gradients bitwise reproducible. The recommendation is to autotune once and pin the kernel options. Source: https://drisspg.github.io/nuggets/FlexAttention-Determinism [read-full]. This flag exists in torch 2.11 (verified).
- FlashAttention (source) exposes `deterministic=` for its backward and supports sm_120 builds, but building it needs nvcc, which is absent here. Source: `third_party/flash-attention` @ `478b5b01` [code-inspected].

### 11.2 Policy [I]

| Mode | Settings | Used for |
|---|---|---|
| **Production** | `CUBLAS_WORKSPACE_CONFIG=:4096:8`, `PYTHONHASHSEED=0`, `TRITON_CACHE_DIR=$REPO/.cache/triton` (pre-warmed, never cleared mid-study), `FLA_CACHE_RESULTS=1`, `cudnn.benchmark=False`, `use_deterministic_algorithms(False)`, TF32 setting logged | All Stage 1–5 runs |
| **Audit** | Production + `torch.use_deterministic_algorithms(True, warn_only=False)`, `torch._inductor.config.deterministic=True`, `torch.backends.cuda.matmul.allow_bf16_reduced_precision_reduction=False` | G0 tests; one rerun of one Stage-2 seed for 1,000 steps |

**Warm the autotune cache** for every (config, seq-len, micro-batch) shape on an **idle GPU** before Stage 2, then archive `.cache/triton` (tar plus SHA-256 in the registry).

**Expected outcome (to verify):** production mode is *statistically* reproducible (G0b), not bitwise.

### 11.3 Deliberate-interruption test (part of G0)

1. Run A: 1,000 steps uninterrupted.
2. Run B: same config, `kill -9` at step ≈ 537 (mid-accumulation), then auto-resume.
3. Compare per-step batch-index SHA-256 (must be identical), the loss trace (bitwise in audit mode; |Δ| < 0.005 at step 1,000 in production) and the final param checksum (audit mode).
4. Repeat with a kill **during checkpoint write** to verify the atomic-save logic.

### 11.4 Checkpoint contents and policy

- **Contents:** model, optimizer, scheduler step, `step`, `tokens_seen`, data cursor (step only, since the loader is a stateless function of (data_seed, step)), RNG states (python, numpy, torch CPU, torch CUDA), config + hash, git commit + dirty flag, library versions, Triton cache hash.
- **Writes:** `torch.save` to `ckpt.tmp`, then `fsync`, then `os.replace` to `ckpt_latest.pt`. Keep the previous file as `ckpt_prev.pt`.
- **Frequency:** every 500 steps or 30 min.
- **Milestones (weights-only bf16, ≈ 0.12 GB each):** tokens {50M, 100M, 200M, 400M, 0.8B (stable/WSD), 1.0B (pre-extension), 1.1B (final)}.
- **Disk:** full checkpoint ≈ 0.7 GB (fp32 weights + 2 Adam moments for ~58M params). Keep only the latest and previous full checkpoints per active run. 47 runs × 7 milestones × 0.12 GB ≈ 40 GB.

- **Outcomes and provenance:** `val_loss_4k`, `val_loss_ext`, `tok_per_s_A`, `tok_per_s_B`, `gpu_hours`, `train_flops_est`, `contended_frac` (fraction of samples with foreign compute processes), `restarts`, `anomalies`, `ckpt_final`, `eval_paths`, `deviation_ref` (decisions.md id), `notes`.

### 12.3 Logging

- **Source of truth:** per-run `runs/<run_id>/metrics.jsonl`, one line per log step with step, tokens, loss, lr, grad_norm, tok/s, max_mem_alloc and GPU temp/util/clock. Eval results go to `experiments/results/<run_id>/<ckpt>/<task>_<len>.jsonl` at item level.
- TensorBoard is optional and is written from the same values.
- W&B offline is not recommended: it adds a dependency and sync state, and gains nothing on a single box [I].
- `stdout` goes to `runs/<run_id>/train.log` and to journald (§13).

## 13. Running jobs and monitoring

- **Persistence:** `loginctl show-user` reports `Linger=no`, so user services stop at logout. The user should run `loginctl enable-linger $USER` once; this is the user's decision and a system setting.
- **Job launch:**
  ```
  systemd-run --user --unit=hyb-<run_id> --collect --same-dir \
    -E CUBLAS_WORKSPACE_CONFIG=:4096:8 -E PYTHONHASHSEED=0 -E TRITON_CACHE_DIR=$PWD/.cache/triton \
    -p MemoryMax=40G .venv/bin/python -m src.train --config configs/<file>.yaml
  ```
  Logs: `journalctl --user -u hyb-<run_id> -f`. Options are from https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html [read-section]. Fallback: `nohup … > runs/<id>/train.log 2>&1 &` (screen/tmux are not installed).
- **Queue:** a single-GPU runner (`src/runner.py`) is itself a systemd-run unit. It takes the next `planned` run from the registry, launches it, waits, and marks it done or failed. It is idempotent: a `running` run with a checkpoint is resumed.
- **Monitor:** run `nvidia-smi --query-gpu=timestamp,temperature.gpu,utilization.gpu,memory.used,power.draw,clocks.sm,clocks_throttle_reasons.active --format=csv -l 30 >> runs/gpu_monitor.csv` and `nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv -l 30` to feed `contended_frac`.
  - Disk guard: do not start a run if free space < 50 GB.
  - Throughput guard: flag if tok/s drops > 30 % below the config's G0 value for > 10 min.
  - Thermal: flag any non-idle throttle reason.

## 14. Plot standards

- Use matplotlib with a project style `plots/style.mplstyle`: 8–9 pt fonts, single-column width 3.4 in, double-column 7.0 in, `savefig.bbox=tight`.
- Output vector **PDF** plus a 300-dpi PNG.
- **Colour:**
  - *ordered* r uses a sequential colour-blind-safe map (`cividis` or `viridis`) with endpoints r=0 and r=1 highlighted;
  - *categorical* task families use the Okabe–Ito palette;
  - markers and linestyles are added so that nothing depends on colour alone.
- **Uncertainty:** 95 % hierarchical-bootstrap bands (alpha 0.2), plus individual seeds as small faint markers. The CI type is stated in every caption.
- **Axes:**
  - composition plots use k (0–12, linear) with secondary tick labels r;
  - length plots use a log₂ x-axis (1K…32K), with the extrapolation region shaded grey;
  - shared y-limits across panels of the same metric;
  - chance/floor and S(1) reference lines; a recovery threshold line at R = 0.8.
- **Frontier plot:** x = inference-state memory at 32K (log scale), y = family score. Draw the endpoint "router line" (H6) and the Pareto front.
- **Reproducibility:** each `plots/make_<fig>.py` reads only `experiments/results/**.jsonl` and the registry, and writes `<fig>.pdf/.png` plus `<fig>.json` (input file hashes, git commit, bootstrap seed). `make plots` regenerates everything. Manual edits are forbidden.

## 15. Required evidence per claim

| Claim type | Minimum evidence |
|---|---|
| "r = 1/4 recovers ≥ 80 % of full-attention retrieval" (H1) | ≥ 3 seeds per config; ≥ 3 ID lengths × 500 items; CI from §6.2 **and** §6.3 above 0.8; gate G2 met; LR rule satisfied |
| "Returns diminish" (H2) | All 7 composition points; ≥ 2 seeds each; CI(g₁ − g_late) > 0 |
| "Task X needs more attention than Y" (H3) | k80 difference CI excludes 0 **and** GLMM interaction passes Holm; both families pass G2 |
| "Placement matters" (H4) | 4 placements at k=3; ≥ 2 seeds each (3 for spread); Holm-corrected pairwise CI excludes 0 **and** ≥ 5 pp |
| "Benefit grows with length" (H5) | ≥ 3 ID lengths; slope CI > 0; extrapolation reported separately |
| "Hybrids beat the endpoint frontier" (H6) | Analytic plus idle-GPU measured cost; hull-margin CI > 0 |
| Any cost/latency number | Idle GPU (G-cost), ≥ 10 reps, median + IQR, session repeated twice, configs interleaved in randomised order, environment logged |
| Any "no difference" claim | Equivalence (TOST) against the pre-registered margin, never a non-significant test alone |
| Comparison to prior work (e.g. Wang et al. 2025, L18) | Stated as "consistent with", with the scale/recipe differences named. Nemotron-H and Waleffe et al. are never described as controlled ratio studies |

## 16. Open questions for the review stage

1. **Elicitation:** can 20–60M base models do RULER-style tasks zero-shot? If G2 fails broadly, options are (a) mixing a small, identical synthetic-task fraction into Stage B data or (b) an identical short post-training (ProLong evaluates after SFT, L24). This changes "data fixed" into "data fixed and identical", and needs a decision.
2. Linear-attention type and its state size are owned by the architecture agent. The memory axis and H6 depend on them.
3. If CARLA cannot be stopped, cost benchmarks need a scheduled idle window.
4. Whether L=12 is fine-grained enough at small r. L=16 allows r = 1/16 and 1/8 but costs ≈ 33 % more per run at equal d.
5. Whether a 3B-token (overtrained) check is worth ≈ 30 GPU-h compared with a second width.
